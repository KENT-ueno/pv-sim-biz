## 1. ペルソナと問い（実装前に固定する。2026-09-20 ユーザー確定）

### 1-1. ペルソナは既存の3モードをそのまま引き継ぐ

風力は**新しいペルソナを作らない**。既存の3つの立場に「オフサイト供給が1つ増える」だけである。

| 需要モード / 事業モード | 使う人 | 風力は何に見えるか | 風力PPA支払は誰のコストか |
|---|---|---|---|
| 産業用・MGタブ ＋ 自家消費型 | 太陽光・蓄電池の**営業担当／EPC**（提案する側） | 需要家に追加提案する電源 | **需要家**のコスト。需要家メリットから引く |
| データセンタータブ | **DC事業者・需要家自身**（設計書 §1 ペルソナ a/b） | 自社で調達する電源 | **自分**のコスト。電気代と並べて見る |
| マイクログリッド（モードB） | **MG事業者**（特定送配電の企画担当） | 網内に供給する電源が1つ増える | **MG事業者**のコスト。運営費に乗り、P-IRRに効く |

**MG事業者から見るとどうなるか（ユーザーからの問い）:**
MGの計算は元々「PV余剰 → 網内需要家に小売価格で売る」構造である。風力はここに供給が足されるだけで、
**計算ロジックは一切変わらない**。変わるのは金の流れの向きだけ。

```
自家消費型・DC:  年間メリット = 電気代削減 + 売電収入 − 風力PPA支払
                 （電気代削減は受電点の基準。届いた風力の託送・賦課金・手数料も引いた値。§5-4）
MG（モードB）:   年間収益    = 網内売電収入 + 系統売電収入 + 束ねメリット
                 年間費用    = 運営コスト + 風力PPA支払 + 届いた風力の託送等   ← ここに入る（W2b）
                 → P-IRR に反映
```

**計算ロジックは変わらない、は W2 の時点の見立てで不十分だった**（風力は送配電網で届くので、敷地内の電源と違い託送等がかかる。
W2c で判明。MGでも同じ扱いが要る）。

MG事業者にとっての意味は「網内の需要家に **24/7に近い電気**を売れる」こと。
テナント誘致の材料になるので、時間一致率はMGモードでも主要な出力にする。

### 1-2. 答えるべき一番の問い

> **24/7（時間単位のカーボンフリー）に近づけるには、何をどれだけ積めばよいか。**

太陽光だけだと、年間電力量で需要の100%を超えても**時間単位の一致率は頭打ち**になる。
このギャップを埋めるのに風力と蓄電池がどれだけ要るかを可視化する。
電気代・CO2・投資回収は**従来どおり出すが、主役ではない**。

主指標:

```
量ベース達成率 [%] = min(1, 年間発電量 / 年間需要量) × 100     ← 従来の「再エネ100%」
時間一致率     [%] = (1 − 年間系統購入量 / 年間需要量) × 100   ← 24/7 の実力
```

この2つの**差**を画面の目立つ場所に出す。蓄電池の放電分は `sc_result["annual_import"]` に
自動で反映されるので、実装コストはほぼゼロ。

## 3. データ方針

### 3-1. 水準と形状の分離（DCの需要モデルと同じ構造）

```
風力発電(t) [kW] = min( 契約容量[kW] × 設備利用率 × 形状(t) ,  契約容量[kW] )
                        └ ユーザー     └ 既定29.1%   └ エリア実績（年平均=1.0）
```

| 要素 | 出どころ | 既定値 |
|---|---|---|
| 契約容量 [kW] | ユーザー入力 | なし |
| 設備利用率 [%] | 資源エネルギー庁 調達価格等算定委員会 第112回（2026年1月）「風力発電について」<br>陸上風力（新設）の想定値。定期報告の実績（2022〜2024年設置の平均値の平均 30.7%、中央値の平均 29.5%）とも整合 | **29.1%** |
| 形状(t) | 一般送配電事業者「エリア需給実績」30分値<br>`風力発電実績 ＋ 風力出力制御量`（＝**抑制前**）を年平均1.0に正規化 | 暦年2025 固定 |
| PPA単価 [円/kWh] | 同委員会 第112回「今年度入札における平均落札価格は11.96円/kWh、上限価格13.00円/kWh」 | **11.96 円/kWh** |

**PPA単価の出典について（2026-09-20 ユーザー提供資料を確認）:** 陸上風力の**公的な価格**は、いずれも
FIT/FIP（国の支援制度）の価格で、**オフサイトPPAの相対契約の単価そのものではない**。PPAの単価に公的な出典はなく、
公的に確認できる中で「実際に事業が成立した水準」に最も近いのが入札の平均落札価格である。

| 資料 | 値 | 意味 |
|---|---|---|
| 調達価格等算定委員会 第112回（2026年1月）「風力発電について」 | 平均落札 **11.96円/kWh**（上限 13.00円） | 2025年度入札（最新）。**既定値に採用** |
| 同「令和7年度以降の調達価格等に関する意見」（2025年2月3日。ユーザー提供） | 平均落札 12.73円/kWh（上限 14.00円） | 2024年度入札（1年前） |
| 同上 結論（p.121〜123）の陸上風力（新設・50kW以上）の入札上限額 | 2024年度 14円 → 2025年度 13円 → 2026年度 12円 → 2027年度 11.8円 | FIP基準価格の上限（入札）。2026・2027年度は第112回で改めて設定し直しとされた |
| 同上 陸上風力（新設・50kW未満）のFIT調達価格 | 14円 → 13円 → 12円 → 11.8円（2024〜2027年度） | 50kW未満。地域活用要件（自家消費・地域消費・地域一体型）を満たすものだけがFIT対象（注７） |
| 同上 陸上風力（リプレース）のFIT/FIP | 12円/kWh（2025年度） | 1,000kW以上はFIPのみ（注８） |
| 同上 想定値（陸上風力・新設） | 資本費27.1万円/kW、運転維持費0.85万円/kW/年、設備利用率29.1%、IRR 6%（2027年度は5%）、運転年数20年（2027年度は25年） | 設備利用率29.1%の出典。**自己所有の風力（v2）の資本費・運転維持費もここが出典** |

より新しい年度の入札結果（11.96円）を既定に置く。単価は入力欄で上書きできる。

**抑制前を使う理由:** 系統都合の出力制御は売る側のリスクであって、風況（資源量）ではない。
買い手への提案では資源量を基準にし、抑制率は別途情報として表示する。

#### 取得時の落とし穴（実測で判明。実装者は必ず読むこと）

1. **User-Agent が要る。** 付けないと 403 で弾かれる
2. **文字コードが統一されていない。** 北海道・東北は cp932（他エリアにはUTF-8のものもある）。
   `cp932 → utf-8` の順でデコードを試す
3. **列は必ず列名で拾う。** エリアによって列数・並びが違う（中国電力には `火力出力制御量` がある等）
4. **ヘッダ行は先頭行ではない。** `DATE` を含む行を探してそこから読む
5. 単位は `[MW平均]` ＝ **30分間の平均電力**。電力量にするには × 0.5h
6. **北海道は月の日数が少ない月を、カンマだけの空行で31日分（1488行）に埋めている。**
   行数を数えるとうるう年でもないのに 372日分（17,856行）になる。日付が空の行は詰め物なので捨てる。

## 4. 前提（2026-09-20 ユーザー承認済み）

| # | 論点 | 本設計の案 |
|---|---|---|
| 1 | オフサイト風力の電気はどこに届くか | **受電点に届く**。**【W2c で改訂】** 当初は「太陽光と同じ扱いで買電を減らし、契約電力も下げうる／託送料はPPA単価に含める」としたが**誤り**だった。届いた電気にも託送の従量分・再エネ賦課金・小売手数料がかかり、契約電力（基本料金）は下がらない（§5-4）。託送の従量分Xと小売手数料Yを入力に持つ |
| 2 | 支払の対象 | **pay-as-produced（全発電量に単価を掛ける）**。余剰・抑制になった分も支払う。結果に「届いて使えた分／無駄になった分」を出して無駄が見えるようにする（W2c で按分から実測の配達量に変更） |
| 3 | FIT売電との併用 | **【W2c で改訂】** 売電・出力抑制の対象は敷地内の太陽光の余剰だけ（風力の余剰は売電できず無駄になる扱い）。よって風力の余剰にFITが付く問題は起きない（W2で出していたFIT注記は不要になった） |
| 4 | 太陽光と風力の同時性 | **METPV-20は平年値、風力は2025年実績で、別のデータ。** 日単位・コマ単位の同時性は担保されない。<br>意味があるのは**月別・時間帯別の平均的な補完関係**まで。画面と文書の両方に明記する |

**4 は本機能の最大の限界。** 「凪と曇天が重なる日」のような評価には使えず、蓄電池のサイジングも
この前提の上での参考値になる。24/7一致率も同じ制約を負う。

### 5-3. `run_simulation` への統合

シグネチャ末尾に**キーワード引数を2つ**追加（DCモードと同じ手口。省略時は従来どおり）。

def run_simulation(..., demand_source=DEMAND_SOURCE_INDUSTRIAL, dc_args=None,

- `pv_enabled=False` のとき `faces=[]` にする（風力単独運転）

  gen_pv    = result["total_gen_clipped"]

#### オフサイト電源（フィジカルPPA）の費用構造

送配電網で届く電気は、需要家が受電点で系統から受ける。次の費用は**削減されない**（出典: [東北電力NW「料金の仕組み」](https://nw.tohoku-epco.co.jp/consignment/pdf/fee_calculation.pdf)、
[自然エネルギー財団 p.10・19・23](https://www.renewable-ei.org/pdfdownload/activities/REI_JPCorporatePPA_2024.pdf)）。

| 費用 | 敷地内PV | オフサイト風力 |
|---|---|---|
| 託送料金（基本料金 円/kW × 契約電力） | 契約電力が下がれば下がる | **下がらない**（受電点の最大は届いた風力も含む） |
| 託送料金（電力量料金 円/kWh × 使用電力量） | かからない | **届いた分にかかる** |
| 再エネ賦課金 | 削減される | **届いた分にかかる** |
| 小売事業者の手数料（バランシング等） | なし | **届いた分にかかる** |
| PPA単価 | （設備投資から逆算） | **発電した全量に**支払う（pay-as-produced） |

#### 計算（受電点の基準。`offsite_receiving` / `offsite_cost_after`）

```
受電量        R(t) = max(0, 需要 + 充電 − 放電 − 敷地内の太陽光)     ← 契約電力・受電上限の基準
小売から買う量      = 運転結果の系統購入 import_(t)                  （風力で賄えなかった残り）
風力の配達量  D(t) = clip(R − import_, 0, 風力発電量)
敷地内PVの余剰(t)  = max(0, PV + 放電 − 需要 − 充電)                 ← 売電・出力抑制の対象はこれだけ
無駄になった風力   = 風力発電量 − 配達量                              （売電できない）

導入後の電気代 = 基本料金(R の最大)                                   ← 風力では下がらない
               + 電力量料金(小売から買う量)                           ← 従来どおり
               + Σ D × (託送の電力量料金 X + 再エネ賦課金 + 小売手数料 Y)
風力PPA支払    = 風力の年間発電量 × PPA単価
年間経済メリット = 電気代削減 + PVの余剰の売電収入 − 風力PPA支払
```

**蓄電池の運転（収支）は太陽光＋風力を合わせた発電のまま**（風力が余る時間に蓄電池が充電し、凪の時間に放電する効果＝24/7の主役を残すため）。
料金だけを受電点の基準で計算し直す。収支の恒等式（残差 ≤ 5e-6 kWh。LPの数値誤差）と、
「太陽光の余剰 ＋ 無駄になった風力 ＝ 運転結果の余剰」は、ルールベース・LPともテストで確認している。

#### 蓄電池LPを受電点の基準で解く（W2d・2026-09-21）。受電上限・最適容量探索との併用

W2〜W2c の蓄電池LPは風力を敷地内の発電と同じに扱って運転を決め、料金だけ受電点の基準で計算し直していた。
このため受電上限（DC）と最適容量探索は評価できず明示エラーにしていた。W2d でLPそのものを受電点の基準にした
（`optimize_battery` / `optimize_battery_capacity` の `offsite` 引数。省略時は従来のLPとビット同一）:

- **変数**: `grid_import` を「受電量 R」（契約電力・受電上限の基準）にし、風力の配達分 `w`（0 ≤ w ≤ そのコマの風力発電量、w ≤ R）を足す。
  **1コマあたり変数が1本増える**だけ（LPの規模は約1.2倍）。`generation_30min` には**敷地内の太陽光だけ**を渡す
- **収支**: R + 太陽光 + 放電 = 需要 + 充電 + 売電 + 出力抑制。**売電・出力抑制はそのコマの太陽光の余剰以下**（風力は売電できない。
  放電を含めないのは、風力を蓄電池に貯めて売る裁定を防ぐため）。小売購入は R − w
- **目的関数**: 基本料金 × max(R)/0.5 ＋ Σ（(R−w) × 小売の電力量単価 ＋ w × (託送X＋賦課金＋小売手数料Y)）− 売電収入。
  風力PPAの支払は発電した全量に払う定数（運転で変わらない）なので**LPには含めず**、最適容量探索の年間メリットから引く
- **受電上限**: R の上限（変数の上限）。風力の配達分も含めて守る。**風力は上限を守る助けにならない**（受電量を増やすだけ）ので、
  事前診断（`diagnose_grid_cap`）は太陽光だけで行う。上限を守れない条件は風力があっても診断を返す
- **結果**: `import_` は小売購入（R − w）。受電量は `offsite_receive`、配達分は `offsite_delivered`（`offsite_receiving` はこれをそのまま使う）。
  導入後ピーク・契約電力は受電量の最大で測る。最適容量探索の年間メリットは、受電点の料金（`offsite_cost_after`）−（風力PPA支払）

**受電点の相殺と、LP内の売電単価（重要）。** 受電点では買電と売電が相殺されて1方向の流れになる（同じコマに買いながら売ることはできない）。
LPの変数では R と売電 E を同時に正にできてしまい、**売電単価が風力の配達単価（託送＋賦課金＋手数料 ≒ 9.3円）より高い（FITの19円など）と、
「風力を受電して太陽光を売る」相殺すれば成立しない裁定**をLPが選ぶ（実測: 仙台の役所＋風力100%＋蓄電池200kWh・売電19円で、年間経済メリットが 312万円/年 と出ていたのが、裁定を除くと 253万円/年。
約60万円/年は、蓄電池の効果ではなく相殺できない運転の分だった。最適容量探索では容量ほぼ0でもこの分が乗り、蓄電池のP-IRRを過大にする）。
売電単価が受電の限界単価以下なら、R と E の関数は凸でLPが厳密に解ける。そこで **LPの目的関数の売電単価だけ**を
`min(売電単価, 風力の配達単価, 小売の最小単価) − 0.01円` に抑える（`offsite_lp_sell_price`。等号だと同値のコマで同時に正になりうるので0.01円だけ下げて厳密に損にする）。
**実際の売電収入・電気代は、返ってきた運転を実際の単価で評価し直す**（`opt_annual_cost` も評価し直した値）。売電単価が低い（既定8.5円）ときはそのまま。
この抑制は運転の最適性を少し損なう（売電を優先すべきコマで蓄電池を優先しうる）が、蓄電池の充電で得る価値（小売単価×効率²≒21円）は売電単価より高いので影響は小さい。
FITと風力を併用する条件でだけ効く。

**検証**（`test_wind_lp.py`）: 独立実装（scipy.linprog。受電点を正味の買い・売りの流れで表す別の定式化）と最適値が一致
（小さな合成データで、売電あり・逆潮流禁止・受電上限あり［周期SOC］・容量が変数のLP）。収支・配達分の範囲・
受電量と売電が同時に正にならないこと・売電は太陽光の余剰だけ・受電量が上限以下・ピーク＝受電量の最大を全ケースで確認。
FIT 19円で裁定が生じないこと、LPがルールベース・蓄電池なしを（受電点の電気代で）上回ることも確認。風力OFFは70項目・MCP12ケースがバイト一致のまま。
**実行時間**: 風力あり＋LP 約6秒、DC＋風力＋受電上限＋LP 約15秒、最適容量探索（段階1＋段階2）約80秒（風力なしで約65秒）。

**変異テスト（2026-09-21）**: LPの定式化・オフサイト料金・`run_simulation` の配線・MCPの27件を壊して検出を確認。26件を検出し、
最初は3件が見逃された（うち2件はテストの穴で補強した: 最適容量探索のシナリオで風力の扱いによる最適容量の差が出ない、
MCPの導入後ピークがLPでは受電量と小売購入で分かれない）。残る1件（LPの売電・抑制の上限に放電を含める）は**等価変異**:
LP内の売電単価を風力の配達単価より低く抑えているため、風力を貯めて売る運転は損で、この制約は結果を変えない
（安全側の二重の防御として残している）。

**ルールベース（W2e・2026-09-21）**: 蓄電池は太陽光の余剰だけを貯め、風力は貯めない。不足分は **風力（届いた分）→蓄電池→小売** の順に充てる
（`simulate_battery` の `offsite_gen` 引数。省略時は従来と同一）。受電上限は強制せず、導入後ピークを受電量（風力の配達分＋小売購入）の最大で判定する。
- **なぜ風力を貯めないか**: W2d までは太陽光＋風力の合算で運転しており、風力の余剰を蓄電池に貯めるために送配電網から受ける量を増やして、
  受電量のピークが上がっていた（実測: 札幌のDC・風力60%・蓄電池3,000kWhで、契約電力が 1,283.6 → 1,739.9kW）。風力は貯めずに受電量を押し上げない
- **なぜ放電を風力の後にするか**: 最初は「太陽光と蓄電池で賄えない分を風力が埋める」（蓄電池が先）にしたが、蓄電池を足すと年間メリットが**下がった**
  （5,631万円。蓄電池なし5,852万円）。風力（約9円/kWh）を蓄電池で置き換えるために、貯めずに売れた太陽光の余剰（FIT 19円）を捨てていたため。
  風力を先にして、蓄電池は風力で賄えない残り（小売から買う分。約23円/kWh）にだけ放電すると、蓄電池なし5,852万円 < ルールベース5,917万円 < LP6,547万円になった
- **受電量**: 風力の配達分＋小売購入（蓄電池の放電後）。放電で受電量が減る。太陽光の余剰だけで充電するので、充電で受電量は増えない
- **限界**: 風力を貯めて凪の時間に使う効果（24/7の主役）は、ルールベースでは出ない。それを見るには最適充放電（LP）を使う。
  契約電力はルールベースでは下がりにくい（上の例では蓄電池なしと同じ1,255.6kW。ルールベースはピークカットを狙わないため）。LPは1,071.3kW

**蓄電池なし**は従来どおり太陽光＋風力の合計で計算し（同じ結果になる）、料金だけ受電点の基準で計算し直す。

## 8. W6: オフサイト太陽光（設計。2026-09-21 ユーザー承認）

**状態:** 設計承認済み・実装は未着手。**想定分担:** 本節＝設計（Opus）／実装＝別セッション（Sonnet）。作業前に §5-4（受電点の経済性）と §6（作業段階）を読むこと。

### 8-1. 目的と範囲

敷地内の太陽光・オフサイト風力に加えて、**需要地とは別の場所にある太陽光発電所から、同じ電力エリア内でオフサイトPPA（フィジカル）で受電する**電源を足す。
問い（§1-2）は変わらない: 「24/7に近づけるには、何をどれだけ積むか」。

オフサイト太陽光は敷地内太陽光と**発電の形が似る**（同一エリア内なら日射が近い）。量ベース達成率は上がるが**時間一致率は伸びにくく、無駄になる分が風力より大きく出やすい**。
この知見を結果に出すことが、この機能の価値の中心である（§8-6）。

**ユーザー判断（2026-09-21）:**
- エリアは **B案**: 全50地点を発電地点に選べる。**託送Xの既定値があるのは北海道・東北だけ**で、他エリアは**手入力必須**（既定値を埋めない。§8-3）
- 太陽光と風力を**両方オフサイトで持てる**（3電源＝敷地内太陽光・オフサイト太陽光・オフサイト風力）
- 24/7 の比較表は電源ごとに行を分ける。オフサイト太陽光の限界を結果に出す
- 電源ごとに X・Y の入力欄を持つ（既定は同一エリアの値）
- **インバランス**: 無駄になったオフサイト分は**対価ゼロの全額損失**という現行の保守的な扱いを変えない（前提として明記する。§8-9）
- **PPA単価**（2026-09-21〜22 改訂。§8-5）: 入札価格をそのまま既定値にするのは乱暴だった。委員会の想定での積み上げ（8.53円）も JPEA の実案件より大幅に低いと分かり、**太陽光の PPA発電単価の既定値は JPEA 15.0円に決定**（§8-5-1。2026-09-22）。積み上げの計算は、前提を見せて調整する手段として残す。
  出典のない部分は**推測して埋めず、調整できる入力にして 0＝未算入と明示**する。全項目に**出典の区分（A〜D・U）を付け**、結果・MCP・README に同じ表示を出す（誠実さの台帳。§9-3）
- 需要の中心は**自家消費（敷地内）**。オフサイトを主にして制御する仕組みはないため、オフサイトはあくまで不足分を埋める電源として扱う（不足分を 風力→蓄電池→小売 の順に充てる現行の順序を変えない）
- **費用の構造は §9（W2f）を使う**（2026-09-22）。W6 は W2f の実装後に着手する

### 8-2. 絞り込み（負担を下げるための決定。承認済み）

- 容量が数値でない・0以下

### 8-7. `run_simulation` への統合（W6-2）

**核心: 単一の `wind_info` を「オフサイト電源のリスト」に一般化する。** W2c〜W2e で、下流はすでにリストを受け取る形になっている（**変更不要**）:

`simulate_battery(offsite_gen=…)`／`optimize_battery(offsite=…)`／`optimize_battery_capacity(offsite=…)`。

**按分は経済性に影響しない**（実測済み。2電源の順序を入れ替えても総額が完全に一致。電源ごとにYを変えても同じ）。よって LP の定式化・ルールベースの順序（風力→蓄電池→小売）は**変更しない**。

### 8-9. 限界と caveats（結果・MCP・README に必ず書く）

1. **余剰とインバランス**: 使い切れずに余った分（発電端）の収入は**需要家に入らない**（全量払いでも余剰の処理は小売が行い、使用量払いでは余剰の収入とリスクは小売のもの。§9-2・§9-4）。余剰精算の入力は設けない（ユーザー判断 2026-09-22）。発電側のインバランス費用は発電バランシング単価、需要側のインバランス費用は小売グロスマージンに含まれる（JPEA の定義。§9-3）
2. **オフサイト太陽光は敷地内太陽光と発電の形が似る**: 量は増えても時間一致率は伸びにくく、無駄になる分が大きくなりやすい（§8-6 の効果表示で見える）
3. **PPA発電単価は相対契約の単価ではない**（§8-5-1 の案のいずれも、実案件の平均または公的データの代理値）。既定値は JPEA 15.0円に決定済み（§8-5-1）
3a. **費用の構造と限界は §9-10 と同じ**（発電バランシング・小売グロスマージンは太陽光・高圧・R4年度の平均。系統設備効率化割引は未算入。小売経由のフィジカルPPAが前提。余剰の収入は需要家に入らない）
4. **太陽光は平年値（METPV-20）**で、風力は2025年の実績（別のデータ。同時性は反映されない）。オフサイト太陽光と敷地内太陽光は同じ平年値なので、この点は影響しない
5. **同一エリア内のみ**。越境託送はモデル化しない。**託送X の既定値は北海道・東北のみ**で、他エリアは手入力（税区分・契約種別・接続区分に注意）
6. 契約電力（基本料金）はオフサイト電源では下がらない。売電・出力抑制の対象は敷地内の太陽光の余剰だけ（風力と同じ）
7. 電源ごとに X・Y が違う値を手入力すると、蓄電池LPの目的関数（電源の年間発電量で重み付けした平均の単価）と事後の評価がわずかにずれる（既定の同一エリアでは一致）
8. 複数DC（会社単位）で拠点間に融通する場合、拠点ごとに受電点・契約電力が別になり、1つのオフサイトPPAを各拠点の不足に配分する構造になる。**W7（今後の課題）**

### 9-1. 経緯（なぜ作り直すか）

W2c の費用構造は `PPA単価 × 発電した全量 ＋ 届いた量 ×（託送X ＋ 賦課金 ＋ 小売手数料Y）` だった。ユーザーの整理（公的データで決まる項目／公的データからの代理値／契約依存の項目）で見直し、
次の不足と誤りが分かった:

1. **公的データで決まるのに入っていない項目が2つあった**: 送電ロス（損失率）と発電側課金（系統連系受電サービス料金）
2. **小売手数料Y（財団の推定 高圧3.0・特高1.5）は、需給調整・小売費用の一括の代用値**だった。JPEA の実績調査で、発電インバランスと小売グロスマージンに分けて置ける
3. **支払の対象は契約で2通りある**（全量払い／使用量払い）。W2c は全量払いだけだった
4. PPA単価（11.96円）は入札の平均落札価格で、**PPAの相対契約の単価そのものではない**（代理値）。しかも**発電側課金を含まない**（調達価格等算定委員会「令和７年度以降の調達価格等に関する意見」p.117:
   2024年度以降の調達価格・基準価格等は「追加的に発電側課金相当額を加えた額とする」）

### 9-2. 費用の式（実装の形）

```
オフサイト電源による需要家の年間費用（小売の料金に含まれない増分。電源ごとに計算して合計）

[全量払い（既定。完全ミラー＝出なり全量）]
  = 発電量G × PPA発電単価
  + 発電側課金                     （発電側課金を「加算」するとき。§9-3）
  + 発電量G × 発電バランシング単価
  + Σ PPA使用量(t) ×（託送電力量料金X ＋ 再エネ賦課金 ＋ 小売グロスマージン）

[使用量払い（部分ミラー＝一部供給）]
  = Σ PPA使用量(t) × 発電側単価
  + Σ PPA使用量(t) ×（託送電力量料金X ＋ 再エネ賦課金 ＋ 小売グロスマージン）
    発電側単価 = ( PPA発電単価 ＋ 発電側課金 ÷ G ) ÷ (1 − 損失率) ＋ 発電バランシング単価
    （JPEA の「売電価格 ＋ 送電ロス ＋ 発電インバランス」と同じ構造。JPEA R4 の送電ロス 0.5円 ≒ 11.3 × 4.7% ÷ (1 − 4.7%) = 0.56円）

発電側課金 [円/年] = 課金対象kW × 基本単価[円/kW・月] × 12 ＋ G × 電力量単価[円/kWh] − 系統設備効率化割引[円/年]
                     課金対象kW = 契約容量（風力の capacity_kw）

量（30分ごとに計算してから合計する。年間で min/max を取らない）
  到達可能量(t) = 発電量(t) × (1 − 損失率)                 … 送電ロスは「量」で扱う。費用項目にしない（二重計上になる）
  受電量(t)     = 需要(t) − 敷地内太陽光(t) ± 蓄電池(t)     … 敷地内で賄った後の不足（自家消費が主）
  PPA使用量(t)  = min(受電量(t), 到達可能量(t))            … 蓄電池LP・ルールベースは既存どおり（到達可能量を上限にする）
  余剰（発電端）= G − Σ PPA使用量(t) ÷ (1 − 損失率)          … 需要地に送られないので送電ロスはかからない
  送電ロス量    = Σ PPA使用量(t) × 損失率 ÷ (1 − 損失率)

小売の料金（今の計算のまま。変更しない）
  = 小売基本料金（託送の基本料金を含む）× 契約電力（受電量の最大。オフサイトでは下がらない）
  + Σ 小売購入量(t) ×（小売電力量単価 ＋ 燃調 ＋ 再エネ賦課金）      小売購入量(t) = 受電量(t) − PPA使用量(t)
```

**守ること（誤りやすい点。ユーザーとの議論で確認済み）:**
- **託送の基本料金は足さない。** 契約電力（受電量の最大）はオフサイトでは下がらず、その基本料金は小売の基本料金（東京電力EPの 1,890円/kW 等）に含まれている。別に足すと二重計上。
  ユーザーの式（需要家の請求を部品に分けた形）では託送基本料金が行として並ぶが、その場合は小売から買う分の費用の行も要る。本ツールは小売の料金を分解しない（内訳は小売ごとに違い非公開）ので、「含まれている」扱いにし、同じ値になる
- **再エネ賦課金の対象は受電量（小売購入量 ＋ PPA使用量）。** 敷地内太陽光の自家消費には課されない（METIの整理: 賦課金は小売電気事業者から供給される電気の使用量に課す）。今のコードはこの形になっている（変更しない）
- **送電ロスを「ロスコスト」の費用項目として足さない。** 全量払いは発電端の全量に払うので、届く量が減ればそれだけで費用が上がる。使用量払いは発電側単価を (1 − 損失率) で割り戻す（上の式）
- **余剰精算は入れない。** 余剰の収入は需要家のものではない（全量払いでも余剰の処理は小売が行い、使用量払いでは余剰の収入とリスクは小売のもの。JPEA p.6・p.29）。
  余剰（発電端）の量は表示する（「使い切れずに余った分。需要家の収入にはならない」）

### 9-4. 支払の対象（全量払い／使用量払い）

JPEA p.29（契約形態の分析）: **完全ミラー**（発電事業者との契約を需要家との契約にミラーし、需要家へ出なり供給＝全量を引き取る）が R4年度ヒアリングで 47%（8件）、
**部分ミラー**（需要家へは一部電力しか供給できず「余剰電力は卸市場へ売電するため量的リスクあり」＝小売がリスクを負う）が 53%（9件）。p.6「発電事業者は小売事業者へ固定価格で全量売電しているが、
小売事業者は需要家へ全量売電できないケースがあり、その場合は小売事業者がプライスリスクを負っている」。

| | 全量払い（既定） | 使用量払い |
|---|---|---|
| 需要家が払う発電側の費用 | 発電した全量（余った分も） | 使った分（PPA使用量）だけ |
| 余剰のリスク | 需要家 | 小売 |
| 余剰の収入 | 需要家に入らない（小売が処理） | 小売のもの |

- **既定は全量払い**（従来の挙動。需要家にとって保守的）
- **使用量払いでは、常に余剰の割合と次の注記を出す**（閾値は置かない。根拠のある閾値がないため）:
  `※ 使用量払いでは、余った電気（発電量の◯%）のリスクを小売が負う前提です。小売グロスマージン 4.1円（JPEA R4 平均。需要に合わせた規模の太陽光が中心）は、この規模の余剰のリスクを織り込んだ値ではありません。実際の契約では単価が上がる可能性があります`
- **蓄電池LP・最適容量探索での使用量払いの扱い（重要）:** LP の目的関数では、届いた分の単価を**全量払いと同じ（託送X＋賦課金＋小売GM）**にし、発電側単価は**事後に**実際の PPA使用量で評価する。
  つまり PPA の電気は「来たら使う」（出なり供給・must-take）として扱う。発電側単価（約14円）＋届いた分の単価（約10円）が小売単価（約23円）を上回ると、LP が PPA の電気を使わない解を選んで
  しまうため（契約上、小売は PPA の電気を先に需要家へ供給する）。LP の「最適化年間コスト」は、どちらの支払の対象でも「受電点の電気代 − 売電収入（オフサイトの発電側の支払を含まない）」と表示する。
  ルールベースの順序（風力→蓄電池→小売）は変えない
- **（2026-09-26 修正。#4）** must-take だけでは、LPが風力を実際より安く見て蓄電池に貯める。使用量払いでは、風力に余剰があるコマで「蓄電池なしでも受ける量」を超える受電に発電側単価を上乗せする（詳細は §9-11 の末尾）。既定の単価では、貯めた風力は0になる

### 9-10. 限界（結果・MCP・README に書く）

1. **発電バランシング 1.1円・小売グロスマージン 4.1円は、太陽光・高圧・R4年度（2022年度）の平均**。風力・特高には暫定。実際の契約で大きく変わる

6. **余剰の収入は需要家に入らない扱い**。使用量払いでは余剰のリスクを小売が負う前提で、その上乗せは小売GMの平均値に含まれる（大きな余剰では楽観的）
7. 使用量払いの蓄電池LPは、PPAの電気を「来たら使う」扱い（発電側単価を最適化に入れない）
8. 電気料金設定は東京電力EPの単価（北海道・東北とのエリアの不一致は既存の制限）

単純に発電側単価を全部LPに見せると、合計約24.5円＞小売約23円なので**LPが風力を全く受けなくなる**（出なり供給の契約と合わない。設計時に must-take を選んだ理由の再確認）。
ユーザーの見立て「単価が正しければ、使用量払いで風力を蓄電池に貯める状況は起きない」を、次の修正（案1）で確かめた:

- 使用量払いでは、オフサイトの電気は消費に先に配分される（出なり）。蓄電池の充電も受電点の内側の消費なので、風力に余剰があるコマで
  受電を増やすと、増えた分は風力になり発電側単価も払う。そこで、**風力に余剰があるコマで、蓄電池なしでも受ける量
  base = min(到達可能量, max(0, 需要−太陽光)) を超える受電に、使用量払いの発電側単価を上乗せする**（`offsite_lp_surplus_penalty`。
  `optimize_battery` / `optimize_battery_capacity`）。LPが「その充電は小売の電気」と言い逃れできないよう、上乗せは届いた量ではなく受電量に課す。
  風力の余剰を超えて受電する分（そこからは小売）も割高に見る保守側の近似（実測ではこの部分は0kWh）。上乗せは判断用で、`opt_annual_cost` からは除く
- 全量払い（上乗せ0）はビット同一。禁止（案2）ではないので、発電側単価が安ければ貯める（テストで確認）
- **実測**（仙台・事務所・蓄電池500kWh/250kW・LP）: 貯めた風力は修正前 1,056／955／20,028／863 kWh → 修正後 8／3／19／0 kWh
  （PVあり風力100%／PVあり30%／PVなし100%／PVなし30%。修正後は計算誤差の範囲）。実際の単価で評価した年間経済メリットは4ケースとも上がった
  （PVなし風力100%で 198,932 → 271,093円）。契約電力は不変。時間一致率は少し下がる（65.9→59.2%。損な運転で水増しされていた分）
- **結論: 既定の単価では、使用量払いで風力を蓄電池に貯める運転は起きない**（ユーザーの見立てどおり）
- 限界: LPは1年を完全に予見した理想運転の上限。オフサイト電源を蓄電池に貯める運転（全量払いのLP）は、発電の予測・計画値を
  蓄電池の制御に使える場合の上限。また使用量払いでは、蓄電池の放電で風力を置き換える効果（実際は約24.5円の節約）をLPは約10円としか見ない（控えめ側）
