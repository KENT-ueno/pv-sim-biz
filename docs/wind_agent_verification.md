> 託送料金の既定値も知りたいです。

| 項目 | 期待値 |
|---|---|
| エリア | 北海道（地点1: 札幌）・東北（地点7: 青森・秋田・盛岡・仙台・山形・福島・新潟）。合計8地点 |
| 東北の月別の形状 | 冬に強く夏に弱い（2月が7月の4倍超。年平均=1.0に正規化） |
| 託送の電力量料金（円/kWh） | 北海道 高圧2.28／特高1.02、東北 高圧2.15／特高0.97（税込表示） |
| 既定値 | 設備利用率29.1%、PPA単価11.96円/kWh、小売手数料 高圧3.0／特高1.5円/kWh（**推定値**） |

### S6. 風力と系統受電上限（データセンター。W2d 以降は計算できる）

> pv-sim-bizで、札幌のデータセンター（IT容量1,000kW・IT負荷率80%・PUE1.4・定常）に、太陽光3,000kW（傾斜30度・真南）と
> 風力（需要の60%）を組み合わせ、蓄電池は最適充放電（LP）で3,000kWh・充放電1,500kW、系統受電上限を22・33kVに収める（9,999kW未満）条件で試算してください。

**期待値（2026-09-21。ローカルの直接呼び出しと本番のMCPで一致を確認）:**

| 項目 | 期待値 |
|---|---|
| 検証（validate） | valid=true。警告に「受電上限は風力の配達分も含めた受電量に対する上限」 |
| 上限9,999kW・LP（3,000kWh・1,500kW） | `grid_cap.status` = `enforced`、導入後ピーク 1,051.1kW（上限以下）、契約電力 導入後 1,051.1kW（導入前 1,120.0kW） |
| 風力（需要の60%）の届いた量 | 4,566,593 kWh |
| 年間経済メリット／時間一致率 | 62,040,389 円/年 ／ 74.9% |
| 同条件でルールベース・上限1,999kW | `not_enforced`、導入後ピーク 1,764.5kW（受電量の最大。小売購入のピークではない）。LPなら下げられる |
| 上限を300kW（手入力）にする | `grid_cap_infeasible: true` の診断（風力があっても風力なしと同じ理由・同じ超過量） |

（上のプロンプトは需要を「定常」にしている。プロンプトの `grid_cap` は `ehv_under_10000kw`。）確認の観点:

- `validate_dc_params` が **valid=true**（W4 のときのエラーは廃止）で、警告に「受電上限は風力の配達分も含めた受電量に対する上限」が出る
- `simulate_dc` が計算でき、`grid_cap.status` が `enforced`、導入後ピーク（`peak_after_kw`）は受電量（小売購入＋風力の配達分）の最大で上限以下
- エージェントが「風力は受電上限を守る助けにならない（受電量を増やすだけ）。上限は太陽光と蓄電池で守る」と説明できるか
- 上限を低すぎる値（手入力で300kWなど）にすると、`grid_cap_infeasible: true` の診断が返り、風力があっても守れない理由（energy／power／capacity）を説明できるか

## 判定

- **数値**: 上の期待値と一致（小数の丸め以外の差は不一致）
- **型**: `generation_kwh` などが**数値**で返る（文字列にならない）
- **2段階プロトコル**: `simulate_*` の前に `validate_*` の内容（特に `wind` の既定値）をユーザーへ提示して確認を取る
- **警告の伝達**: S3 の「契約電力は下がらない」「同時性の限界」「手数料は推定値」、S4 の量ベース達成率と時間一致率の差が、回答に含まれる
- **誤解釈の防止**: 風力を敷地内の太陽光と同じ扱い（契約電力が下がる・賦課金が削減される・余剰が売電できる）で説明していない
